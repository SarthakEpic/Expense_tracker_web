# Deploying Expense Tracker Web (free)

The recommended free deployment pairs two services that are free **forever** (no
credit card, no expiring trial):

| Piece | Service | Free tier | Role |
|---|---|---|---|
| App | [Render](https://render.com/docs/free) | Free web service (512 MB) | Runs FastAPI + Uvicorn, deploys from GitHub |
| Database | [Neon](https://neon.com/pricing) | Free Postgres (0.5 GB, scale-to-zero) | Stores transactions + budgets persistently |

Why a database service? Most free app hosts use an **ephemeral disk** — a
SQLite file inside the container would be wiped on every restart or wake from
sleep. Pointing the app at Neon keeps financial data durable. Locally nothing
changes: without `DATABASE_URL` the app still uses `expenses.db` SQLite.

---

## One-time setup (~10 minutes)

### 1. Create the Neon database

1. Go to [neon.com](https://neon.com) and **Sign up with GitHub** (no card).
2. Create a project named `expense-tracker` (pick the region closest to you).
3. Open the project dashboard and copy the **pooled connection string**
   (the hostname contains `-pooler`). It looks like:
   ```
   postgresql://USER:PASSWORD@ep-xxxx-pooler.REGION.aws.neon.tech/neondb?sslmode=require
   ```

### 2. Generate your login credentials

On your machine, inside the project:

```bash
python create_user.py
```

Enter a username and password. Copy the resulting `APP_USERNAME` and
`APP_PASSWORD_HASH` values from `.env` — you'll paste them into Render next.

### 3. Deploy to Render

[![Deploy to Render](https://render.com/images/deploy-to-render-button.svg)](https://render.com/deploy?repo=https://github.com/SarthakEpic/Expense_tracker_web)

Or manually: **Render dashboard → New → Web Service → connect this GitHub
repo**. Render auto-detects [`render.yaml`](render.yaml) (Blueprint) and asks
for the private values:

| Variable | Value |
|---|---|
| `DATABASE_URL` | The Neon **pooled** connection string from step 1 |
| `APP_USERNAME` | From step 2 |
| `APP_PASSWORD_HASH` | From step 2 |

`SECRET_KEY` is auto-generated by the blueprint and `TZ` defaults to
`Asia/Kolkata` — adjust both in the dashboard if needed.

For the manual path (if not using the blueprint): runtime **Python**, build
command `pip install -r requirements.txt`, start command
`uvicorn main:app --host 0.0.0.0 --port $PORT`, health check path `/health`.

### 4. Verify

1. Wait for the first deploy to finish (2–3 minutes).
2. `curl https://YOUR-SERVICE.onrender.com/health` → `{"status":"ok"}`
3. Open the app URL and log in with the credentials from step 2.

On first boot the app copies your env credentials into its `app_users` table.
From then on, **change your username/password right in the app**:
**Settings → Login credentials**. The new values take effect immediately — no
redeploy, no env edits.

**Forgot your password?** Open your Neon project's **SQL editor** and run
`DELETE FROM app_users;`, then restart the Render service ("Manual Deploy →
Restart" or suspend/resume). On boot the app re-seeds from the env vars, and
you can log in with those.

## Environment variables

| Variable | Local dev | Cloud (Render) | Description |
|---|---|---|---|
| `APP_USERNAME` | required | required | Login username — seeds the app database on first boot |
| `APP_PASSWORD_HASH` | required | required | PBKDF2 hash from `create_user.py` — seeds the app database on first boot; later changes happen in the app's Settings page |
| `SECRET_KEY` | required | required (auto-generated by blueprint) | Session signing secret |
| `DATABASE_URL` | unset (uses `expenses.db` SQLite) | required | Postgres connection string; enables the Postgres engine |
| `TZ` | system | recommended (e.g. `Asia/Kolkata`) | Timezone for transaction timestamps |

## Free-tier behavior & gotchas

- **Sleep:** Render free services spin down after 15 minutes without traffic.
  The next visit takes roughly a minute to wake. This is the main trade-off of
  the free tier. (Optional workaround: a free cron-ping service hitting
  `/health` every 10 minutes keeps it warm — but it burns the free compute
  hours and is against the spirit of the free tier.)
- **Database cold start:** Neon suspends compute after ~5 minutes idle; the
  first query after that adds well under a second.
- **Data safety:** transactions live in Neon (0.5 GB free — decades of
  personal ledger data). Use the built-in CSV export for regular backups, and
  Neon's branch/snapshot features for point-in-time copies.
- **Auto-deploy:** every push to `main` redeploys the app automatically.
- **Schema migrations:** `init_db()` runs on boot and creates/extends tables
  idempotently on both SQLite and Postgres.

## Running the test suite against Postgres

CI runs the suite on both engines (see `.github/workflows/ci.yml`). Locally:

```bash
# SQLite (default)
python -m pytest -v

# Postgres (e.g. a local container)
docker run -d --name pg-test -e POSTGRES_PASSWORD=postgres -e POSTGRES_DB=expense_test -p 5433:5432 postgres:16
DATABASE_URL=postgresql://postgres:postgres@localhost:5433/expense_test python -m pytest -v
```

## Rejected alternatives (and why)

- **Koyeb / HF Spaces / most container free tiers:** ephemeral disk — the
  SQLite file is wiped on restart, losing your data.
- **Render free Postgres:** expires ~30 days after creation.
- **PythonAnywhere free:** WSGI-only; cannot serve an ASGI FastAPI app.
- **Fly.io / Railway:** trial credits or paid, not free.
- **Oracle Cloud Always Free VM:** genuinely free and would let you keep plain
  SQLite, but requires manual cloud signup and server administration.
